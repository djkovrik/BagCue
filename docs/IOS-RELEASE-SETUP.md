# BagCue iOS macOS continuation and link guide

This is the project-specific continuation guide for QG-003/QG-010. Windows generated and inspected repository contracts but did **not** run CocoaPods, Xcode, an iOS simulator/device, code signing, Firebase console setup, or an Apple archive.

## Required Mac

- macOS runner/developer Mac with Xcode 26.2 or newer (Firebase Apple 12.18.0 requirement), selected by `xcode-select`.
- JDK 17, Git LFS, Ruby, CocoaPods 1.16.2, and network access to CocoaPods CDN.
- Bundle ID `com.sedsoftware.bagcue.iosApp`; scheme `iosApp`; workspace `iosApp/iosApp.xcworkspace`; deployment target iOS 16.2.

## Exact checkout and setup

```bash
git clone https://github.com/sedsoftware/BagCue.git BagCue
cd BagCue
git lfs pull
java -version
xcodebuild -version
sudo xcode-select --switch /Applications/Xcode_26.2.app
gem install cocoapods --version 1.16.2 --no-document
pod install --project-directory=iosApp --repo-update
open iosApp/iosApp.xcworkspace
```

Open the workspace, select `iosApp`, choose the Apple team/signing profile, and confirm the bundle ID without changing it. After registering that exact Apple app, place the real Firebase config at `iosApp/iosApp/GoogleService-Info.plist`, add it to the `iosApp` application target, and commit it directly. The file is repository configuration, not a GitHub secret; never invent or reuse another app's file.

`Podfile` pins `FirebaseAnalytics/Core` 12.18.0 (the no-IDFA Analytics subspec) and YandexMobileAds 8.4.0. The Kotlin `shared:platform` CocoaPods contract exposes modules `cocoapods.FirebaseAnalytics` and `cocoapods.YandexMobileAds`. Yandex 8.4.0 transitively packages AppMetrica support frameworks, including `AppMetricaAdSupport`; BagCue's iOS configuration remains null and never initializes or requests through Yandex. Keep `Podfile.lock` generated by this exact install and review any dependency update before committing it.

## `Test and link iOS` parity commands

```bash
./gradlew :shared:domain:iosSimulatorArm64Test \
  :shared:data:iosSimulatorArm64Test \
  :shared:network:iosSimulatorArm64Test \
  :shared:platform:iosSimulatorArm64Test \
  :shared:component:catalog:iosSimulatorArm64Test \
  :shared:component:templates:iosSimulatorArm64Test \
  :shared:component:session:iosSimulatorArm64Test \
  :shared:component:history:iosSimulatorArm64Test \
  :shared:component:settings:iosSimulatorArm64Test \
  :shared:root:iosSimulatorArm64Test \
  :shared:compose:linkDebugFrameworkIosSimulatorArm64

xcodebuild -workspace iosApp/iosApp.xcworkspace -scheme iosApp \
  -sdk iphonesimulator -configuration Debug \
  -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO build
```

The repository targets ARM64 iOS simulators. On an Apple Silicon Mac use the commands above unchanged. An Intel Mac can cross-compile and link the same candidate by adding `ARCHS=arm64 ONLY_ACTIVE_ARCH=YES` to `xcodebuild`, but it cannot execute the ARM64 Kotlin/Native simulator tests; those tests must complete on the `macos-15` ARM64 CI runner. Compose Multiplatform 1.12.0 does not publish an `iosX64` runtime variant.

Expected evidence: every test exits zero; `compose.framework` links; Xcode resolves FirebaseAnalytics and YandexMobileAds without duplicate/undefined symbols; the built app reports bundle ID `com.sedsoftware.bagcue.iosApp`; EN/RU native/Compose resources are packaged.

## Nullable advertising and analytics checks

- iOS must provide `adUnitId = null`; repository, Podfile, plist and CI must contain no production or demo Yandex ad unit. With no load call, the linked SDK must issue no ad request.
- Exercise denied/required/allowed region and consent states and confirm packing remains usable. Inspect device/network logs for no ad request in all iOS builds.

- The official Yandex demo ID may be used only in a separately edited, locally invoked diagnostic build that cannot be selected by CI/release; remove it and prove a clean diff afterward. This is optional and is not release evidence.
